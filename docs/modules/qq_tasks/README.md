# QQ 音乐免费任务与每日定时

在 QQ 音乐设置中保存登录态和歌手选择，然后点击「执行任务」。默认的「自动执行全部已支持的免费任务」会按服务端实时任务及本地已验证的能力选择任务，不固定保存某一时刻的类型名单。关闭该模式可按类型自选，空列表明确表示全部不选；自动模式不会扩展用户已经选择的歌手范围。

## 当前接入范围

| 项目 | 执行方式与限制 |
| --- | --- |
| 积分中心、乐迷勋章每日签到 | 提交官方签到请求并读取状态 |
| 免费浏览、支持的微博访问 | 真正访问官方入口，满足服务端条件后上报，再核对任务进度 |
| 乐迷点赞 | 对排行榜实际未点赞对象执行点赞，再核对进度 |
| 歌词卡每日签到 | 读取当前阶梯凭证、提交签到、复查已签到状态 |
| 官方盖楼游戏 | 仅适配 `game.y.qq.com/tmegames/web_pages/qm_tonglou/index.html`；真实点击开始、按画面位置释放方块、等待官方页面结算，不看广告、购买体力或伪造游戏请求 |
| 添加小勋播放器 | 校验官方任务入口；仅免费、已解锁且没有其他艺人绑定时设置一次，之后复查使用状态、艺人绑定和勋章任务 |
| 普通歌词卡单抽 | 需单独开启「允许使用已有普通抽卡次数」；明确排除超会/付费卡池，已有次数不足不购买，每个未完成任务最多使用 1 次 |

所有动作均以服务端重新返回的任务进度作为完成依据。操作返回成功但任务进度未变时显示未确认；复查失败时保留原进度，不制造完成状态。写请求失败或结果不明确时不盲目重试。日志中的“未完成”包括未尝试和已执行待确认；“本次未处理”只统计没有实际执行的任务，待确认项目会单独列出。付费及未开放任务也会分别说明，不混入需手动完成列表。

## 仍需官方客户端的任务

广告依赖真实广告 SDK 的播放完成事件及凭证；听歌依赖客户端实际播放记录；歌曲/勋章分享依赖客户端成功回调。农场和合成游戏尚无已验证的免费操作流程，继续显示需手动。勋章任务入口提供有效 starlight 翻卡网址时，现有浏览器流程会先确认免费次数和简单难度，再实际配对；是否完成仍以勋章任务列表回读为准。歌词卡签到页自身的翻卡挑战仍保留手动入口。唱歌应援需要实际制作演唱。不能因为任务免费或带有上报标志就直接提交完成条件。

## 每日定时

在设置中开启「每日定时执行」并保存时间，格式为 `HH:MM`，统一使用北京时间。预设时间为 09:30，定时功能默认关闭；必须保持应用后台服务运行。应用启动晚于当日设定时间会补跑当天一次。任务忙、没有登录态或任务全关时会延后检查，不占用当天触发记录。

每天在 `data/qq_tasks/schedule_runs/YYYY-MM-DD.json` 保存一次触发记录，防止重启和多个进程重复触发。同一天已触发后再修改时间或重新开启，不会重复执行。定时触发记录不代表任务成功，完成情况应看任务进度与日志。若进程在占位后、启动前退出，当天需手动补跑。

配置新增字段：`auto_all_free`、`card_draw_enable`、`schedule_enabled`、`schedule_time`。已有 Cookie、歌手选择与其他配置保留。
